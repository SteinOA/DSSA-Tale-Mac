RUTING SOM BØR IMPLEMENTERES AV HOVEDARBEIDET
Behold eksisterende generiske Metal/CPU-server og begge NB-modellfiler.
Velg denne separate serveren automatisk bare for eksplisitt gjenkjent
Apple M4-familie når encoder, alias og binær finnes, og GPU/Metal er valgt.
CPU-modus skal ALLTID bruke original server og dermed respektere CPU-valget.
Ukjent prosessor og nyere M-familier skal foreløpig bruke original server.
Ikke utled støtte fra høyere tall, eller merk Intel-støtte.
M4 er faktisk prøvd; M4 Pro/Max og andre maskiner er ikke fysisk prøvd her.

Serveren er kompilert med WHISPER_COREML_ALLOW_FALLBACK=ON. Dette gjør at
manglende Core ML-last kan falle tilbake, men status skal si faktisk motor.
Kun «Core ML model loaded» bekrefter at encoder ble lastet; COREML=1 er
bare byggestøtte. Ved startfeil bør originalserver kunne brukes uten å
endre brukerens språk, modellvalg eller lydruting.

CPU_AND_NE gjelder encoder. Dette utelukker Core ML-GPU, men både CPU og
Neural Engine er tillatt. Decoder bruker fortsatt Metal. Faktisk ANE-
utførelse er ikke profilert, så grensesnittet må ikke hevde dette sikkert.
q5-valget blir en hybrid: kvantisert q5-decoder + encoder fra full NB-modell.
Dette skal beskrives; det er ikke en ren q5-encoderbane. Fullvalget beholder
samme modellfamilie og encodervekter med FP16 Core ML-beregning.

OPPSTART/MINNE
Første Core ML-last var 24,7s; senere 11,6–17,6s; q5-kandidat 13,6s.
Bruk minst 120s oppstartsfrist og vurder varm modell før diktering.
Vis klargjøring; ikke la modellen se frosset ut. Oppstart er tregere enn
original Metal (ca1–2s i prøvene). Konvertering peakRSS4,71GB; dette er ikke
appens runtime-minnekrav. Runtime øker minnebruken, og bredere prøver på
24GB-maskiner gjenstår. Appen må ikke automatisk avslutte andre programmer.

otool bekrefter minOS26.0 og kun Appleframeworks/systembiblioteker.
Faktisk OS-test: M4/macOS27.0.1; macOS26 er teknisk minimum, ikke prøvd.

convert-nb-encoder.py --model <full-GGML> --output <egen mappe>
kontrollerer SHA256 før lesing, og rekonstruerer kun 487 encoder-tensorer.
Ingen modellnedlasting skjer. requirements-frozen.txt låser prototypevenv;
bruk separat venv, aldri mottakerens system-Python. Konvertererens CLI og
syntaks er kontrollert; selve vekt-/Core ML-logikken er identisk med den
kjørte prototypen. En ren reproduksjonsrunde av CLI-innpakningen gjenstår.
Originalens format følger convert-pt-to-ggml.py fra samme pinned fork.
Manifestet inneholder kildeoffset, type, dimensjoner og SHA for hver tensor.
Interface er logmel_data float32[1,128,3000] -> output float32[1,1500,1280].
Compiled modellen bruker specificationVersion6 og intern FP16.
